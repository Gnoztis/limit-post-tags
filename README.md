# Limit Post Tags

Ограничивает список меток под записью: показывает первые пять и добавляет
кнопку «Ещё N меток», которая раскрывает остальные. Список не обрезается по
высоте — кнопка встаёт сразу после последней видимой метки.

Версия 1.7.7. Требуется WordPress 7.0+, PHP 8.4+.

## Установка

1. Скопировать каталог `limit-post-tags` в `wp-content/plugins/`.
2. Активировать плагин в разделе «Плагины».

Настроек в админке нет. Плагин не хранит настроек и не пишет в базу ничего,
кроме кэша проверки обновлений — двух транзиентов, которые удаляются при
удалении плагина.

## Что делает плагин

| Что | Как |
|---|---|
| Показывает не больше 5 меток | лишние элементы (ссылка или обёртка) получают класс `lpt-hidden`, контейнер — `is-collapsed`; CSS скрывает их |
| Кнопка «Ещё N меток» | встаёт в конец списка, сразу после последней видимой метки |
| Число N | считается по фактическому числу скрытых ссылок-меток, с правильным склонением: «1 метка», «2 метки», «5 меток» |
| Раскрытие и сворачивание | по клику контейнер получает класс `is-expanded`, подпись кнопки меняется на «Свернуть»; повторный клик возвращает исходный вид |
| Скринридеры | у кнопки `type="button"`, `aria-expanded` и `aria-controls` |
| Без обрезки по высоте | снимаются `line-clamp`, `max-height` и `overflow`, поэтому кнопка всегда видна |

По умолчанию плагин работает со списком меток в контейнере `.post-meta__tags` —
так его выводит тема сайта. Метка — это прямая ссылка `<a>` или прямая обёртка
(`<span>`, `<li>`) ровно с одной ссылкой внутри; обёртки без ссылок и с двумя и
более ссылками не считаются. Класс `lpt-hidden` ставится на сам элемент метки —
ссылку или обёртку, поэтому скрытая обёртка не занимает место. Другой контейнер
задаётся фильтром `lpt_container_selector`, см. «Настройка».

## Кнопка «Ещё N меток»

Кнопка создаётся, только если скрыто не меньше двух меток. Поэтому при шести
метках видны все шесть: скрыта одна, и кнопка не появляется. Порог меняется
фильтром `lpt_min_hidden_to_collapse`.

## Настройка

Лимит, порог кнопки, контейнер списка меток и полное отключение задаются
фильтрами в теме или mu-plugin:

```php
// Показывать 8 меток вместо 5 (допустимо от 1 до 50).
add_filter( 'lpt_max_tags', static fn(): int => 8 );

// Создавать кнопку уже при одной скрытой метке.
add_filter( 'lpt_min_hidden_to_collapse', static fn(): int => 1 );

// Другой контейнер списка меток (по умолчанию `.post-meta__tags`).
add_filter( 'lpt_container_selector', static fn(): string => '.entry-tags' );

// Полностью отключить плагин на сайте.
add_filter( 'lpt_enabled', '__return_false' );
```

Числовые значения приводятся к целому и ограничиваются диапазоном 1–50, поэтому
`0`, отрицательное число или строка не ломают вывод. Селектор должен быть
валидным CSS-селектором: символы, которые могут разорвать `<style>` или
`querySelectorAll()`, отбрасываются, и берётся значение по умолчанию.

## Обновления

Плагин обновляется штатным механизмом WordPress из репозитория
[Gnoztis/limit-post-tags](https://github.com/Gnoztis/limit-post-tags): берётся
более новая версия из последнего релиза GitHub и тегов вида `vX.Y.Z`; при
равенстве версий выигрывает релиз — у него есть описание изменений. Архив —
zip-ассет релиза или zipball GitHub. Пакет принимается только по `https` и
только с доменов GitHub.

Проверка кэшируется на 6 часов, ошибка — на 15 минут. Кнопка «Проверить
обновления» в строке плагина сбрасывает кэш и игнорирует паузу после ошибки.
Если проверка не удалась, причина видна в строке плагина и в уведомлении на
странице «Плагины» — например «403 (лимит GitHub API)».

### Токен GitHub (необязательно)

Без токена GitHub разрешает 60 запросов в час на IP. Одному плагину этого
хватает, но несколько WordPress-сайтов на одном хостинге делят лимит: когда он
исчерпан, проверка возвращает 403 и обновления перестают находиться. Токен
поднимает лимит до 5000 запросов в час.

Подойдёт fine-grained personal access token с доступом только на чтение:
Repository access — нужный репозиторий (или Public repositories), Permissions —
Contents: Read. Токен нужен только для запросов к GitHub API; на установку
обновлений он не влияет.

Задать в `wp-config.php`:

```php
define( 'LPT_GITHUB_TOKEN', 'github_pat_…' );
```

или фильтром `lpt_github_token`. Значение нигде не выводится; без токена плагин
работает как раньше.
